# 分析数据样板

这个目录放的是**免扫失效的排查样板**：某一时刻、本机全部沙箱的免扫状态截面。

## 为什么要有它

以前排查「qb4 为什么又要扫码」，只能翻自己的日志，看完只知道自己这个号出事了，
判断不了这属于**孤立事件**还是**这批号都在退化**。

把 16 个号的链龄、换新次数、密钥年龄、最后返回码摆在一起，异常的那个会自己跳出来：

```
| qb4  | 1.9d  | 27.4h | 需扫码 |
| qb8  | 24.8d |  4.1h |        |
```

qb4 的 1.9 天对着别人的 12～25 天 —— 一眼就能看出问题不在"服务端固定一天寿命"，
而是在这个号自己的保活路径上。

## 怎么采

界面右上角 **「采集数据样板」**，或命令行：

```powershell
.\JskpBoxManager.exe samples
.\JskpBoxManager.exe samples --appdir C:\application\jskp-qb-portable
```

每次生成 `samples\<yyyyMMdd-HHmmss>\`，落在**程序目录**下（不是仓库目录）。

## 采出来的是什么

| 文件 | 内容 |
|------|------|
| `摘要.md` | 先看这个：横向对照表 + 逐号细节 + 自动体检 |
| `摘要.json` | 同一份数据的机读版，方便以后写脚本对比 |
| `events.jsonl` | 本机全部 ilink 事件（key-rotated / key-revoked / need-scan / scan-login / refresh） |
| `<qbN>.rotate-log` | 每次换 key 的记账（哈希 + 原因） |
| `<qbN>.probe.json` | 最近一次主动探测的结果与返回码 |
| `<qbN>.renew-attempt` | 未确认的续期标记（存在时预检与探测会跳过该号） |
| `<qbN>.need-scan.txt` | 待扫码标记与原因 |
| `<qbN>.history-cooldown.json` | 历史凭证的冷却名单 |

**只有哈希与数值，没有任何明文密钥。**

## 摘要怎么读

| 列 | 含义 | 异常信号 |
|----|------|----------|
| 链龄 | 从最近一次**扫码**到现在的天数 | 多数号 10～25 天、个别 1～2 天 → 那个号有问题 |
| 换新 | 这条链一共免扫换过多少次 key | 明显少于链龄天数 → 保活没在干活 |
| 今日 | 今天已换次数 / 每日上限 | 贴着上限 → 有东西在反复滚 key |
| 密钥年龄 | 当前这把 key 多久前写入 | 很新却已被拒 → 死的不是密钥，是整条链 |
| 授权剩余 | 按 30 天扫码窗口还剩多少天 | 接近 0 → 正常到期，不是故障 |

「自动体检」那一段是程序按规则自动标出来的可疑点，规则都很保守
（例如链龄不足本机中位数的三分之一、密钥不到 3 小时就被判废）。

## 三类已知失效（对照用）

1. **被别处扫码顶掉** —— 整条链一起失效（连几十天前的历史 key 全部 `-13`），只能重扫。
2. **保活根本没跑** —— 链龄短、换新次数少，日志里是 `refresh skipped: ...`。
3. **本地凭证坏了但服务端还认** —— 历史 key 里有一把返回 `0`，用「历史凭证恢复」就能救。

## 约定

- `samples/*/` 不进版本库（见 `.gitignore`）：事件里带 uin，不宜外传。
- 例外：`autoauth-样本-20261110/` 特意入库 —— 那是 `-13` 拒绝响应的首次实测留档，
  只保留结构摘要（已去掉 uin 和完整报文），供以后对照。
- 要发给别人排查请用界面上的「导出诊断包」。
- 想长期观察某个号：出问题当天采一次、恢复后再采一次，两份放一起对比。
