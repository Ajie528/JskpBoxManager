# 可选技能读取：已打通（OCR 方案）

> 2026-11-18 完成。能**稳定读出当前 4 张可选技能**。

## 结论

### ✅ 能做到

每次运行都能准确读出当前技能选择界面的 4 张卡：

```
[1] 干冰弹增伤
[2] 火焰侵袭
[3] 爆炸增伤
[4] 齐射+
```

连续两次运行结果完全一致。

### 方法：截图 OCR + 词典纠错

```
1. PrintWindow 截游戏窗口（能截到被遮挡的窗口，不要求置前）
2. 在卡牌区（窗口高度 42%~80%）扫描白色文字行
3. 把连续行聚成「文字带」，选其中能分成 3~5 列的那个（= 4 张卡的标题行）
4. 按列空隙切出每张卡的标题
5. 放大 12 倍 + 二值化 → tesseract(chi_sim, --psm 7)
6. 用 57 条已知技能名词典做模糊纠正（共同字符数 / 较长长度 ≥ 0.45）
```

### 为什么用 OCR 而不是内存

内存路线已经试过 8 种方法，都拿不到「当前这 4 张」：

| 方法 | 结果 |
| --- | --- |
| 找技能名（UTF-8/UTF-16） | 只命中本地化字符串池、压缩配置包 |
| 找 length=4 的 `List<int>` | 十几个候选，全是通行证/UI名/哈希表 |
| 找 length=4 的对象数组 | 全是字符串池对象 |
| 反查描述字符串引用 | 追到哈希表条目，是**全量卡牌表**不是当前 4 张 |
| 内存差分（选卡前后） | 战斗中每秒几百个数值在变，噪音淹没信号 |
| 搜 4 个等级值的组合（11,7,2,2） | 命中的是渲染顶点数据 |
| 解 UnityFS 资源包（10550 个全扫） | 4 张卡里 3 张的名字**不在本地资源里** |
| IL2CPP 元数据查类 | `GameLogic` 程序集里没有战斗技能类 |

**根因**：迷宫技能池由服务端动态下发，当前 4 张是运行时生成的，
数据很可能由 Unity 引擎层持有（不在 wasm 线性内存的 il2cpp C# 堆里）。

### 已确认的内存结构（仍有价值）

虽然拿不到「当前 4 张」，但摸清了这些：

**① 全量卡牌名表**：150 个「整卡」字符串对象（如「干冰弹增伤整卡」），
是固定的枚举表，按顺序排列在 `0x3C4863DA780` 一带。

**② 卡牌名 → id 字典**：每组 0x20 字节

```
+0x00  klass = 0x0E055F90
+0x04  0
+0x08  hash = 0x19AAE539（如干冰弹增伤整卡）
+0x10  value → 字符串对象
```

**③ 内存里能解码的字符串对象**：每条 32 字节

```
+0x00  klass = 0x0349FD10 (System.String)
+0x08  length
+0x0C  UTF-16 数据
```

**④ 迷宫状态**（完全可用，见 `事件id对照表.md`）

## 已知限制

| 情况 | 表现 |
| --- | --- |
| 界面没打开（不在选技能） | 报「没识别出技能卡」 |
| 窗口被最小化 | PrintWindow 可能截到黑屏 |
| 全新的技能名（不在词典里） | OCR 原文可能带 1~2 字误差，但会原样输出 |
| 需要 tesseract | `C:\Program Files\Tesseract-OCR\`，含 chi_sim |

## 提高精度的做法

**扩充词典**是最有效的。当前词典 57 条，覆盖了内存里确认过的全部卡牌名。
新遇到未收录的技能时，把 OCR 原文和实际名字补进去即可。

词典位置：`ReadSkills.ps1` 里的 `$knownSkills`。

## 与内存方案的关系

- **迷宫状态**（行/列/层/币/积分/左右箭头界面）：用内存，快（2 秒）且准
- **可选技能**：用 OCR，约 9 秒，准确

两者互补。如果以后找到可选技能的内存地址，可以替换 OCR。
