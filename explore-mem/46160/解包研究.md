# 解包研究：技能配置在哪

> 采集：2026-11-18 19:35~20:00

## 关键结论

### 1. 已成功解包 UnityFS AssetBundle

写了一个极简解包器（`UnityFs.cs`），支持：
- 头部解析（`UnityFS` + version 8 + unity 2021.3.30f1）
- LZ4 块解压（自实现 `Lz4.DecompressBlock`）
- blocksInfo 自适应定位（本游戏的包在 flags 后有填充，偏移不固定）

实测：`resbin_pack_002` 解出 **3.8 MB**，`resbin_pack_001` 解出 **277 KB**。

### 2. 【重要】4 张卡里有 3 张不在本地资源里

扫描全部 **10550 个 .ab 包**，搜 4 个技能名：

| 技能名 | 是否在本地资源 |
| --- | --- |
| **猛烈震荡** | ❌ 不在 |
| **燃料改良** | ❌ 不在 |
| **散射小冰弹** | ❌ 不在 |
| **制导激光** | ✅ 在（`resbin_pack_001` 系列） |

**这解释了为什么一直找不到**：
迷宫技能池是由**服务端动态下发**的，本地只有配置模板（id、描述、图标名），
具体「这一局给你哪 4 张」的列表运行时才生成，且名字可能存在内存里的临时字符串。

### 3. 配置表结构已能读出

解出来的数据里能识别出配置表名：

```
AutoChessMonsterLibraryConfig
AITaskConfig
BattleLevelUpConfig
BattleDynamicGrowConfig
BianShenBaseConfig
BianShenSkillActivateConfig
AchieveBaseConfig
AutoChessDivisionConfig
AutoChessFetterConfig
AutoChessGemLibraryConfig
```

技能描述记录的实测结构（`0x324C8` 一带）：

```
u32 标记（0x02000001 变体）
u32 字符串字节长度
UTF-8 字符串 + 0x00
8 字节 key（如 0x0000000001C62973）
```

示例：

```
+0x324C8  "制导激光伤害"    key=0xC62973_18
+0x324F8  "冰暴发生器伤害"  key=0xC72973_18
```

## 4. 命令

```powershell
# 解包并看数据大小
MemProbe abs 路径\xxx.ab

# 解包到文件
MemProbe abdump 路径\xxx.ab 输出.raw

# 在解出的数据里搜关键字
MemProbe abfind 路径\xxx.ab "技能名"

# 扫描整个目录（10550 个包，约 5 秒）
MemProbe abscan 目录 "关键字1" "关键字2"

# 按「长度+UTF8+key」结构解析表
MemProbe abtable 输出.raw 0x起点
```

## 5. 下一步该怎么走

既然 3/4 的技能名不在本地，**继续解包的收益很低**。可选：

### A. 找服务端下发的技能池（推荐）

迷宫开局时服务端会下发技能池和本次可选项。这条路能拿到**确切的 4 张卡**。
线索：`0x3C0044xxxxx` 那段内存是压缩的配置，可能是解压后的协议数据。

### B. 用「制导激光」做锚点验证

`制导激光` 在本地配置里，且当前也是 4 张卡之一。
可以：找到它在内存里的**配置对象**（不是字符串），看配置对象被谁引用，
从而定位到「当前 4 张卡」的容器。

### C. 定位 `RougeTowerRandomSkillSelectUI` 实例

需要先找 Unity native 堆（不在 wasm 内存里）。
