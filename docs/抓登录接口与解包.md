# 抓登录接口与解包

目标：弄清「向僵尸开炮」拿到 `wx.login` code 之后，往哪个业务 URL 发什么参数（以便脚本用 code 换业务 Token）。

两条路一起用：

| 方式 | 命令 | 产出 | 适合 |
|------|------|------|------|
| CDP 拦 `wx.request` | `capture qbN` | `logs\wxapi-qbN.jsonl` | 录真实请求/响应 |
| 解包 wxapkg | `unpack qbN` | `logs\wxapkg-qbN\` | 看静态登录逻辑、补 CDP 漏掉的 |

第三条路（抓真实请求/token）：`hook`（Frida）现在也截业务 HTTPS 明文，见下方「4」。

> 为什么 `capture`（CDP）抓不到：小游戏跑在 `WeChatAppEx.exe` 里，而它启动时**没有** `--remote-debugging-port`，CDP 连不进它的 `wx` 上下文。QQ 浏览器调试口（9301）只有游戏中心启动页。所以真实 code/token 要靠 Frida（本页 4）。

---

## 1. CDP 抓包（`capture`）

在 **PowerShell / cmd** 里进入安装目录再跑（不要双击 exe；PowerShell 必须加 `.\`）：

```powershell
cd E:\game_script\jskp-box-manager\dist\JskpBoxManager-1.5.1
.\JskpBoxManager.exe capture qb1 --seconds 120
.\JskpBoxManager.exe capture qb1 --no-launch --no-stop --seconds 180
```

若窗口一闪而过或「没反应」：看同目录 `logs\qb1.log` 里有没有 `capture 开始抓`——有就说明其实已启动（WinExe 以前不弹控制台；1.5.1 起诊断命令会挂到当前终端或弹出黑窗）。

- 默认会停箱再冷启，尽量挂到**开局那一次**登录请求。
- `--no-launch`：挂到已经开着的游戏上（只能抓之后的请求，开局包可能已经发过）。
- 在调试口上对各个 Target 注入：包一层 `wx.request` / `wx.login`，原样放行，事件进 `__jskpCap`，主机轮询写出。

日志每行一条 JSON，常见字段：

- `ev=login`：`code` / `errMsg`
- `ev=request`：`method` / `url` / `header` / `data`
- `ev=response`：`statusCode` / `data`
- `ev=fail`：失败信息

若一直 0 条：多半是 WeChatAppEx 小游戏 JS 上下文没出现在 QQ 浏览器的 CDP Target 里。这时以 `unpack` 为主，或再查 WeChatAppEx 是否自带 `--remote-debugging-port`。

## 2. 解包 wxapkg（`unpack`）

```text
JskpBoxManager.exe unpack qb1
JskpBoxManager.exe unpack qb1 --out D:\tmp\jskp-wxapkg
```

会：

1. 在沙箱 live、金库 `wmpf`、运行时目录里找 `*.wxapkg`（带本游戏 AppID 的优先）。
2. 尝试明文、AppID 异或、MD5(AppID) 异或等常见形态。
3. 解出文件；扫描文件名/内容里的 `login` / `code2session` / `session` 等，写入 `login-hints.txt`。
4. `packages.json` 列出找到的包路径。

**请先启动过一次游戏**，否则沙箱里可能还没有包。

解包后可在输出目录里搜：

```text
login
code2session
js_code
session_key
openid
```

## 2.0 实测已验证（keylog + 抓包解密，2026-11-02）

用 `keylog` + Wireshark/tshark 对真实登录抓包解密，拿到明文全链路（HTTP/2 over TLS 到 `*.scgame.com.cn`）：

```
GET https://h5api.scgame.com.cn//login/login_wxmg.php
    ?sdk_version=1.1.9&scene_wx=1168&system_version=Windows%2010%20x64
    &wx_sdk_version=3.10.3&wx_client_version=3.7.6
    &appid=1048&js_code=<wx.login 的一次性 code>&uuid=&game_client_version=
```

登录成功后，游戏拿返回的字段去调 `web-t5game2.scgame.com.cn/auth/auth_sdk/auth.php`，其查询串里能看到登录产物：
`ret=0&uin=<数字uin>&token=<URL编码的业务token>&open_id=<openid>&wx_mg_appid=wx31a9c726536cdacc&sdkAppid=1048&...`

即 `login_wxmg.php` 返回 `{ret, uin, token, open_id, wx_appid, ...}`，与 `get_wx_code.py` 解析字段一致。`uuid` / `game_client_version` 实测可为空。

启动顺序还会调 `/dir/minigame.php`、`/ver/check_ver.php`、`/notice/get_notice.php` 等，均为 HTTP/2。

## 2.1 实测结论：「向僵尸开炮」业务登录接口

由 `unpack qb1` 解出 `__WITHOUT_MULTI_PLUGINCODE__\game.js`（游戏 SDK 配置 `appId:"1048"`、`baseUrl:"https://h5api.scgame.com.cn/"`）：

```text
GET https://h5api.scgame.com.cn/login/login_wxmg.php
    ?appid=1048                 # 游戏内部 appid（不是 wx31a9c726536cdacc）
    &js_code=<wx.login code>
    &uuid=<本地存储 uuid，可空>
    &game_client_version=<可空>
```

返回 JSON：`ret == 0` 成功；失败看 `info`。成功字段：`open_id`、`uin`、`wx_appid`、**`token`**（业务 Token）。

包结构：游戏主体在 `_wasmcode_.wxapkg` / `_wasmcode1_.wxapkg`（Unity WebGL 编译的 wasm），登录/支付等 JS 胶水在 `__WITHOUT_MULTI_PLUGINCODE__.wxapkg` 的 `game.js`。

`scripts/get_wx_code.py qb1` 已把这一步接上：取 code → 调上面接口 → stdout 输出 `{"token","uin","open_id","wx_appid"}`。

## 3. 建议流程

1. 本机用管家正常登录进游戏一次（保证有包、有会话）。
2. `unpack qb1` → 看 `login-hints.txt` 和可疑 `.js`。
3. 再 `capture qb1`（或游戏开着时 `--no-launch`）→ 对照 `wxapi-qb1.jsonl` 里真实 URL/body。
4. 把「code → 业务 Token」的那一条请求格式接到 `scripts/get_wx_code.py` 后面。

## 4. Frida 抓真实登录请求与 token（`hook`）

`WeChatAppEx` 没有调试口，CDP 取不到；用 Frida 挂进 `WeChatAppEx`，截 BoringSSL `SSL_write`/`SSL_read` 的明文，直接拿到游戏正常登录时发的 `login_wxmg.php` 请求（含 `js_code`）和返回（含 `token`）。

前置：Python 3 + `py -3 -m pip install frida psutil pefile`（`hook` 会自动装）。

```powershell
cd E:\game_script\jskp-box-manager\dist\JskpBoxManager-1.5.1
# 冷启动并抓 120 秒：弹二维码就扫，进游戏那一下就会发登录请求
.\JskpBoxManager.exe hook qb1 --seconds 120
# 游戏已经开着、想抓后续登录/重连：
.\JskpBoxManager.exe hook qb1 --no-launch --no-stop --seconds 180
```

看 `logs\frida-ilink-qb1.txt` / `.jsonl`：

- `[已挂上 SSL 明文] ... funcs=[SSL_write@..., SSL_read@...]`：钩子挂上了。
- `[HTTP明文] ... write ... GET /login/login_wxmg.php?...js_code=...`：请求（含 code）。
- `[HTTP明文] ... read ... {"ret":0,...,"token":"..."}`：返回（含业务 token）。

只上报命中 `login_wxmg` / `scgame.com.cn` / `js_code=` / `"token"` 等关键词的明文，不会把全部流量倒出来。

若出现 `[警告] 未找到 SSL_write/SSL_read 导出`：说明这版 `WeChatAppEx` 的 BoringSSL 被静态链接/裁剪，导出名不可见，需要改用特征码定位（后续再做）。把 `.jsonl` 发我即可判断。

> 只读观测，不改包、不发请求。`js_code` / `token` 是敏感值，`.jsonl` 不要外发。

## 4.0 一条龙：`token`（已端到端实测）

装了 Wireshark 后，一条命令自动「抓包 + keylog 冷启动登录 + 解密提取」：

```powershell
cd E:\game_script\jskp-box-manager\dist\JskpBoxManager-1.5.1
.\JskpBoxManager.exe token qb1
```

stdout 输出一行 JSON（供脚本解析）：

```json
{"ok":true,"appid":"1048","wx_appid":"wx31a9c726536cdacc","js_code":"...","token":"...","uin":"356625842","open_id":"..."}
```

自动：找 tshark（Wireshark 自带）→ 选活动网卡 → 解析 scgame IP 做抓包过滤 → 定时抓包同时冷启动免扫登录 → 用导出的密钥解密 → 提取 `login_wxmg.php` 的 `js_code` 与后续 `auth.php` 的 `token/uin/open_id`。

参数：`--seconds`（默认 130）、`--iface \Device\NPF_{GUID}`（手动指定网卡）、`--keep`（保留 pcap 供排查）、`--no-stop`（结束不停箱）。

> 需要抓包权限（Npcap，装 Wireshark 时勾选）。pcap 默认用完即删；`token-qbN.pcapng` 与 `sslkeys-qbN.log` 含真实凭证，别外发。

## 4.1 实测：Frida SSL 导出挂钩失败，改用 TLS 密钥日志

实测 `hook qb1` 的 SSL 钩子三进程全报 `ssl-missing`：业务 TLS 在 `flue.dll`（174MB，Chromium 本体）里，BoringSSL 静态内链、`SSL_read`/`SSL_write` 不导出符号。

但 `flue.dll` 编进了 **`SSLKEYLOGFILE`** 支持。于是用 `keylog` 导出 TLS 会话密钥，配合抓包解密（已实测密钥能导出）：

```powershell
cd E:\game_script\jskp-box-manager\dist\JskpBoxManager-1.5.1
# 先开 Wireshark 抓包（过滤 host h5api.scgame.com.cn），再：
.\JskpBoxManager.exe keylog qb1 --seconds 180
```

`keylog` 会：设 `SSLKEYLOGFILE` 环境变量 → 走正式 launch 冷启动免扫进游戏 → 把密钥导出到 `logs\sslkeys-qbN.log` → 打印 scgame 的 IP 和 tshark 解密命令。

解密（需装 Wireshark）：

```powershell
tshark -r 抓到的.pcapng -o tls.keylog_file:"logs\sslkeys-qb1.log" ^
  -Y "http.request || http.response" -T fields -e http.request.full_uri -e http.file_data
```

解出的就是 `GET /login/login_wxmg.php?...js_code=...` 及返回的 `token`。

> 环境变量经 Sandboxie 传进箱内，Chromium 启动时读取。密钥文件能解密你所有 TLS 流量，别外发。

## 5. 复制令牌失败

界面「复制令牌」若提示 `OpenClipboard 失败 (CLIPBRD_E_CANT_OPEN)`，一般是输入法/剪贴板工具占用。1.5.1 起会自动重试；仍失败会弹出可全选文本框。也可直接打开程序目录里的 `protocol.json` 看 `token` 字段。
