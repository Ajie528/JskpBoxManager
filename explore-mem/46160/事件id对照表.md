# 迷宫事件 id → 界面语义 对照表

> 数据来源：**实测点击 + 截图确认**，不是猜的。
> 采集：2026-11-18，游戏版本 2.212，沙箱 qb1

## 核心结论（先看这个）

### 1. `CurSelectCol` = 格子的 **类型（type）**，不是选项序号

实测三次，全部吻合：

| 操作 | 画面箭头指向 | CurSelectCol | 对应格子 | 弹窗 |
| --- | --- | --- | --- | --- |
| 点左箭头（row1→2） | 购物车 | **1** | `#1(类型1,事件0)` | **商店** |
| 点右箭头（row1→2） | 扳手 | **2** | `#2(类型2,事件1000)` | **安全区** |
| 点左箭头（row2→3） | 僵尸/NPC | **2** | `#4(类型2,事件0)` | **本层怪物**（战斗预览） |
| 点右箭头（row2→3） | 问号 | **3** | `#5(类型3,事件1090)` | **随机事件** |

**`CurSelectCol` 的值 = 那个格子的 `类型` 字段。** 这个关系非常干净。

### 2. `类型` 字段 = 该行第几列（1-based）

看 row=3 的三个格子：

```
#3(类型1,事件1000) ← 第1列
#4(类型2,事件0)    ← 第2列
#5(类型3,事件1090) ← 第3列
```

而画面上 row=3 只有 **2 个箭头**，因为它们从当前列（类型2）出发：
- 左箭头 → 类型2（同列，走上去）
- 右箭头 → 类型3（右移一列）

**第1列（类型1）走不到，所以没有箭头指向它。**

### 3. 可选项的判定规则（修正版）

```
可选项 = 上层行(row = 当前行+1)里，类型 ∈ { 当前类型, 当前类型+1 } 的格子
```

不是「全部上层格子」。这解释了为什么 row=3 有 3 格但只有 2 个箭头。

## 字段语义（全部实测）

### 格子 `CSMessMapData`（每格 40 字节）

| 偏移 | 字段 | 含义 | 实测值 |
| --- | --- | --- | --- |
| +0x00 | klass | 类型指针 | `235227840`（固定） |
| +0x04 | — | 恒为 0 | 0 |
| +0x08 | **类型** | 行内第几列（1/2/3） | 见上 |
| +0x0C | **事件 id** | 决定弹什么界面 | 0、1000、1090… |
| +0x10 | **row** | 行号（层） | 1~11 |
| +0x14 | **美术 id** | 格子外观样式，**不是位置** | 2、12、22、32、102、201、301、411 |
| +0x18 | 标志 | 0 或 3 | |

**`+0x14` 美术 id 在同一行内会重复**（row=9 三格全是 102），所以不能用它判定左右。

### MazeDataMgr（对象基址 +0x00 起）

| 偏移 | 字段 | 含义 |
| --- | --- | --- |
| +0x00 | `CurSelectRow` | 当前选中的目标行 |
| +0x04 | `CurSelectCol` | **当前选中格子的类型值（= 行内列号）** |
| +0x10 | `m_curLevel` | 当前层（画面「2/3层」） |
| +0x18 | `m_curRow` | 角色当前所在行 |
| +0x1C | `m_curCol` | 角色当前所在列（类型值） |
| +0x20 | `m_mazeCoin` | 迷宫币 |
| +0x24 | `m_mazeScore` | 本期积分 |
| +0x3C | `m_highestMazeScore` | 本期最高分 |
| +0x44 | `FinCnt` | 完成计数 |
| +0x58 | `m_listCSMessMapData` | 格子列表指针 |

### 怎么算「左箭头是什么、右箭头是什么」

```
当前列 = m_curCol（对象 +0x1C）
上层   = row == m_curRow + 1 的所有格子

左箭头 = 上层里 类型 == 当前列       的格子（直行）
右箭头 = 上层里 类型 == 当前列 + 1   的格子（右移）

每个箭头的内容 = (该格子的类型, 该格子的事件id) → 查表得到界面
```
