# 过期提醒（微信推送）

当某个账号的免扫凭证**超过 20 小时没有续期**时，通过微信推一条提醒，避免一路拖到过期才弹码。

只提醒，不自动处理。续期仍按 `docs/保活选项说明.md` 的规则执行。

---

## 1. 支持的渠道

| 渠道 | 需要填 | 说明 |
|------|--------|------|
| **PushPlus**（推荐） | token | <https://www.pushplus.plus> 微信扫码登录，复制 token。免费额度够用 |
| **Server酱** | SendKey | <https://sct.ftqq.com> 微信登录取 SendKey |
| **Bark** | key 或完整地址 | iOS 用；填 key 即可，也支持 `https://api.day.app/xxx` |
| **自定义 Webhook** | 完整 URL | POST JSON：`{"title":"…","content":"…","text":"…"}` |

前两个都推到微信，配置最简单。

---

## 2. 配置

### 界面

主界面右侧 → 选中任意沙箱 → **过期提醒（微信推送）** 一行的 **设置…**，
打开独立的「过期提醒设置」窗口：

1. 勾选「凭证超时未续期时推送提醒」
2. 选渠道（默认 PushPlus）
3. 粘贴 token / SendKey
4. 「超过 20 小时提醒，同一账号 6 小时内不重复」——按需要改
5. 点 **保存**，再点 **发送测试** 确认能收到

「立即检查」会马上扫一遍所有沙箱并推送（用于验证或手动排查）。

> 这个窗口是独立弹窗，不是右侧窄面板里的内嵌控件——右侧只显示一行摘要，
> 避免说明文字被裁掉。

### 配置文件

程序目录 `notify.json`：

```json
{
  "enabled": true,
  "channel": "pushplus",
  "token": "你的token",
  "warnHours": 20,
  "repeatHours": 6
}
```

`channel` 取值：`pushplus` / `serverchan` / `bark` / `webhook`。

---

## 3. 命令行

```text
JskpBoxManager.exe notify             扫描一遍，有超期就推送
JskpBoxManager.exe notify --test      发一条测试消息
JskpBoxManager.exe notify --check     同 notify
```

配合 `--appdir 目录` 可指定含 `profiles` 的安装目录。

退出码：`0` 正常（含「没有超期」）、`1` 发现超期但推送失败、`2` 未配置。

---

## 4. 主动探测（提前确认凭证还有效）

除了「按时间提醒」，还可以让程序**主动连服务器验证凭证**——这是提前发现过期最可靠的方式。

勾选「定时连服务器验证凭证是否还有效」并设间隔（默认 120 分钟，**最短 30 分钟**）后，程序会：

1. 挑出**已停止**的沙箱（运行中的自动跳过）
2. 对每个沙箱真实发送一次 AutoAuth
3. 看返回码：

| 返回 | 含义 | 程序动作 |
|------|------|---------|
| `0` | 凭证有效 | 顺带把 key 换成新的，继续运行 |
| `-13` / `-14` / `-2` | **已失效** | 立刻标「需要扫码」并推送提醒 |
| 网络错误 | 暂时连不上 | 不标记，下一轮再试 |

### ⚠ 频率不能调太高（真实踩过的坑）

**AutoAuth 是「轮换」语义：探一次就换一把 key，协议层做不到「只验证不换」。**

2026-11-07 凌晨 qb4 就是被每 2 分钟的探测连滚了 4 次 key：

```
02:00:56  01434ec7 → c75696d5
02:01:50  c75696d5 → 224ce8f3
02:03:50  224ce8f3 → 036d9d87
02:04:42  036d9d87 → 339d7bc6
```

当天下午 15:27，这条号的**整条授权链被服务端作废**——连 10 月 31 日的历史 key
逐一试过都返回 `-13`，只能重新扫码。

所以现在有双重保护：

| 保护 | 值 |
|------|-----|
| 最短探测间隔 | **30 分钟**（设更小会被自动抬到 30） |
| 每号每天最多换 key | **8 次** |

换 key 记录在 `logs\qbN.rotate-log`，可用它回看某个号一天换了几次。

命令行一次性探测：

```text
JskpBoxManager.exe notify --probe
```

输出示例：

```text
qb1   有效（已换新 key）
qb16  已失效：凭证已被服务端作废（-13）：多半是同一微信号在别处扫码顶掉，需要重新扫码
探测完成：15 有效，1 失效/失败，0 跳过
```

> **只探测已停止的沙箱**。运行中的 `WeChatAppEx` 内存里握着旧 key，
> 服务端作废旧 key 后它会把旧值写回文件并断掉游戏会话
> （qb15 实测续期成功 2 秒后游戏窗消失）。所以正在玩的一律跳过，不冒这个风险。

## 5. 什么时候会自动检查

| 时机 | 说明 |
|------|------|
| 每次保活跑完 | `refresh` 结束后顺手扫一遍全局 |
| 界面开着时 | 每 10 分钟检查一次（按时间阈值提醒） |
| **开启主动探测后** | 每 N 分钟（默认 2 分钟）真实连服务器验证一次 |
| 手动 | 界面「立即检查」或命令行 `notify` / `notify --probe` |

---

## 6. 判定规则

- 「凭证年龄」取 **live 与金库中较新那个** `tdi_account.txt` 的写入时间，所以刚扫码不会被误判。
- 超过 `warnHours`（默认 20 小时）才算超期。
- 同一把 key 在 `repeatHours`（默认 6 小时）内只提醒一次；**换了新 key 或已续期，记录自动清除**，下次超期能立刻再提醒。
- 凭证无效（未登录 / 已标需要扫码）的账号不提醒——那类问题在界面「登录」列已经标红。

状态文件：`logs\notify-state.json`。

### 6.1 「需要扫码」不等于凭证真的废了

实测 qb10 / qb12：`need-scan` 挂了 4 天（11-03 → 11-07），期间每天保活只写一行
`refresh skipped (need QR scan)`。但金库里 10-16 / 10-18 的旧 key **一直有效**，
协议续期一次就换成了新 key——这两个号白白浪费了 4 天。

1.5.25 起，启动和保活都会在判定「需要扫码」之前先试一次金库：

```
live 无效 + 金库有未作废的凭证 + 沙箱已停  →  推金库回 live，再走正常流程
```

只有金库也无效、或那把已被登记作废时，才真的要求扫码。
服务端对真停用的 key 会回 `-13`，多试一次不会造成损害。

## 7. 推送内容长什么样

```text
向僵管家：3 个账号超过 20 小时没有续期

以下账号的免扫凭证已超过 20 小时没有换新，有掉线/弹码风险：

· qb3（黑皇奥德彪）：25.3 小时，已停止
· qb8（小叄相见恨晚）：23.1 小时，游戏中
· qb2（简单）：21.4 小时，已停止

请打开管家确认：如果是游戏一直开着，关掉游戏就会自动续期；
如果已停箱，可以直接点「⚡ 纯协议续期」。
```

## 8. 排障

| 现象 | 处理 |
|------|------|
| 测试收不到 | 检查 token 是否复制完整；PushPlus 关注公众号了吗；Server酱的 SendKey 是否失效 |
| `code=903 用户令牌不正确` | token 填错或已重置，重新复制 |
| `code=400` 之类 | 多为当日免费额度用完，换 Server酱或明天再试 |
| 命令行说「没有超期」但界面显示很久没续 | 界面看的是「免扫链」天数；提醒看的是**这把 key 的写入时间**，两者不同 |
| 想临时关掉 | 取消勾选「凭证超时未续期时推送提醒」并保存，或把 `enabled` 改 false |
