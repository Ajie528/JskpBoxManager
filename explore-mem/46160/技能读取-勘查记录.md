## 2. 已确认的内存结构

### 2.1 il2cpp 字符串对象（每条 32 字节）

```
+0x00  klass      = 0x0349FD10（System.String）
+0x04  monitor    = 0
+0x08  length     = 字符数
+0x0C  UTF-16 字符数据（从这里开始）
```

**字符串数组可以整片解码**：`MemProbe strarr 0x地址 条数`

## 3. 为什么没打通「4 张卡的技能 id」

### 试过的方法

| 方法 | 结果 |
| --- | --- |
| 搜技能名（UTF-8） | 只命中本地化表和压缩配置包 |
| 搜技能名（UTF-16） | 命中字符串池，是静态资源 |
| 找 length=4 的 `List<int>` | 找到十几个候选，逐个验证都是别的东西（通行证技能 1013/1023/1033/1043、UI 名、哈希表） |
| 找 length=4 的对象列表 | 全是字符串池对象 |
| 反查字符串引用 | 能追到字典条目，但那是全局词条表 |
| 内存差分（选卡前后） | 战斗每秒几百个数值在变，噪音淹没信号 |
| IL2CPP 元数据查字段 | `GameLogic` 程序集里没有战斗技能类 |

### 根因判断

1. 战斗技能数据**不在 C# 逻辑堆**（`GameLogic` 程序集无对应类），可能由 Unity/Cocos 组件层持有。
2. 技能名只是**静态字符串资源**，不绑定「当前这 4 张卡」。
3. 选卡界面的 `m_listChooses` 实例还没定位到。
